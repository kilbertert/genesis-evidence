# 莱可服商品打标操作清单

> **2026-09-30 状态：本清单已被执行过一轮，且结论与清单的初始建议不同。**
> 实际使用的类别方案见 `docs/condition-to-mall-tag.md` 的映射表与「验证状态」一节。
> 下面保留原始清单是为了记录**当时要求运营做什么**；它不是当前的真值，逐字照抄会建出
> 一套与现状不符的标签。要看「现在应该是什么」，看映射表。

**用途**：由**莱可服的运营**在商城后台 `https://admin.mall.qushiyun.com` 上操作，把「健康方向」与「商品」连起来。做完之后，检测页才能按健康风险取到对应商品。

**为什么必须由运营在后台做**：标签是租户自己的数据（`goods_label` / `goods_label_option` / `goods_spu_label`），入口就是商城后台的商品编辑页。第三方只能读，写不了；绕过去直写库等于越过对方的管理界面。

**当前状态（2026-09-29 实测）**：莱可服用八个常见类别名查询**全部返回空**，在售商品也**没有挂任何标签**。**这不等于「莱可服没有任何标签类别」**——按类别名查询只能证明「这八个名字下没有类别」，**不能证明别的名字下没有**。所以第一步是**先看后台现有的标签类别全表**（见下），有可用的就沿用，没有才新建。

## 一、要建什么

### 1. 建一个标签类别

| 项 | 建议值 | 说明 |
| --- | --- | --- |
| 类别名 | ~~`慢病风险`~~ **（2026-09-30 实际未采用）** | **建议用这个名字**：公司体系内既有的健康方向标签词汇（`saas/healthcare` 的 `YunZhenGoodsLabel`）用的就是这个类别名，沿用可与既有词汇对齐。**但请先看后台已有的类别全表——若已有承载同类含义的类别，直接用它，不要新建。** |

**标签名也是必填项**。商城的结构是三层：**类别 → 标签名 → 取值**。

- 映射表最终记的是 **（标签名, 取值）**这一对，**不是（类别名, 取值）**——两者都要准确；
- **如果标签名与类别名写成一样**（例如都叫 `慢病风险`），可以省事：**请明确告诉我们「标签名与类别名相同」**；
- 如果写成别的名字（例如类别 `慢病风险`、标签名 `健康方向`），**请告诉我们实际的标签名**。名字错一处，取商品时就静默返回空。

把**当前在售的每一件商品**，按它实际对应的健康方向**勾上对应的取值**（一件商品可以挂多个）：

| 商品 | 建议挂哪个取值（由你们按实际功效决定） |
| --- | --- |
| 当前在售的每一件商品 | 按该商品的实际功效，选择上表中对应的取值（一件可挂多个） |

**我们不改商品与功效的对应关系**——哪个商品适合哪个健康方向，是你们的经营判断。我们只要求：**在勾选完成后，把「商品 → 取值」的对应关系告诉我们**，以便核对。

## 二、怎么操作（商城后台）

1. 打开 `https://admin.mall.qushiyun.com`，用**莱可服租户的操作员账号**登录（**不要用超管 `system`**——那是平台账号，不是租户运营身份）。
2. 商品 → 标签：**先看现有的类别全表**。有可用的就沿用，没有才**新建标签类别**（类别名按上表）。
3. **无论是否沿用了类别，都要核对并补齐下面两样**：该类别下的**标签（记下它的名字）**与该标签下的**取值**（上表列出的全部取值）——**只建类别不建标签与取值，商品是挂不上去的**。
4. 商品 → 商品列表：**编辑每一件商品**，在标签处勾选，保存。
   > ⚠️ **编辑商品时务必把该商品原有的标签一起带上再保存**——服务端是**整组替换**：更新商品时若提交的标签列表为空，服务端会**删掉该商品的全部标签且不写回**（这是服务端保存逻辑本身的行为，不可逆）。
5. 建完后**通知我们**，我们读回来逐字核对。

---

## 三、建完之后我们做什么

1. **读回来核对**：逐个类别与取值查一遍，确认名字与你们报的一致（商城按**字符串精确相等**匹配，写错不报错、只返回空商品）。
2. **填映射表**：把实际取值填进 `docs/condition-to-mall-tag.md`。
3. **端到端确认**：在检测页上确认对应健康风险下**确实出现商品**——这一步才叫验证通过。

## 四、需要你们回复我们的四件事

1. **标签名**实际用的是哪个（若与类别名相同，说一声「与类别同名」即可）；
2. **类别名**实际用的是哪个（建议 `慢病风险`，或你们现成的类别）；
3. **12 个取值**实际用的是哪些名字（可用上表建议名，也可沿用现有取值）；
4. **商品与取值的对应关系**（哪件商品挂了哪个取值）。

> **前两项缺一不可**：商城的查找用的是 **（标签名, 取值）**，类别名只是分组。只报类别名与取值，我们仍可能取不到商品。
