# 生产队列口径（2026-10-17）

这份记录只做一件事：把**同三个数字**的三种读法钉死。它们在本项目里各自误导过至少
一次，每次的方向都一样——把**合规的终态**算成**待办**，于是下一个读者去补一件
已经做完的事。

数据取自服务宿主生产库的只读副本（2026-10-17）。

## 一、"有全文但没有抽取" ≠ 待抽取

| 口径 | 数字 | 含义 |
| --- | ---: | --- |
| `full_texts` 有行、`paper_extractions` 无行 | 79 | **不是待办** |
| 其中，筛选阶段已排除 | 59 | `ScreeningExcluded`，重跑无意义 |
| 其中，从未入队，且采集成员行显示已排除 | 12 | 同上 |
| 其中，作业在队列里 | 8 | 只有这 8 条是"待抽取" |
| 其中，排除后再判为 eligible | **7** | 2026-10-17 已跑：7/7 完成、零失败 |

**判据**：先用 `collection_papers.title_abstract_decision` / `full_text_decision`
按 `core/store/screening.py` 的 `not_excluded_sql` 分流，再谈"待抽取"。
`paper_extraction_jobs` 的 `failed` 同样不能当失败数读——先按 `error_class` 分组；
本批 85 条 `failed` 里 **85 条都是 `ScreeningExcluded`**，真失败为 0。

## 二、"有全文但没抽取 / 没全文" 里，绝大多数是**版权终态**

"eligible 但没有全文"曾被我记为 121 篇并当作主线瓶颈。实测是 151 条成员行，
其中：

| 状态 | 条数 | 性质 |
| --- | ---: | --- |
| `not_retrieved`，**有具名原因** | **147** | **闭合终态，不是待办** |
| `pending` | **4** | 真正的待取全文 |

147 条的原因分布：

| 原因 | 条数 |
| --- | ---: |
| 全文版权不允许证据处理 | 116 |
| Europe PMC 许可元数据阻止项目存储全文 | 14 |
| 题录相关但来源未提供可合法处理的全文（显式记为 `not_retrieved`，不作科学排除） | 10 |
| 其他许可/标识缺失 | 7 |

**判据**：`not_retrieved` + 非空 `full_text_retrieval_reason` + reviewer + 时间戳
= 满足台账闭合条件，是**结论**。只有 `pending` 才是"还没取"。

**这也意味着"缺全文"不是主线的可解瓶颈。** 147 条里 140 条是版权/许可的硬约束，
补采集不会改变它；剩下 7 条是可再试的来源标识问题。

## 三、那 4 篇 `pending` 全部卡在同一个死锁上

4 篇的 `title_abstract_decision` **全部为 NULL**，分布在两个主题：

| 论文 | 主题 |
| --- | --- |
| `4de1e17d` | `nutrition-ckd-risk` |
| `c868a8ff` / `7d211d15` / `cf581a18` | `nutrition-electrolytes` |

这正是 ADR 0015 记录的死锁：无全文 → 自主路径不筛查 → 不检索 → 无全文。
**修复前，这 4 篇永远取不到全文，也永远不进入抽取。** 修复后它们会被筛为
`included` 并进入检索。

## 四、主题台账：28 个里 26 个已闭合

| 状态 | 主题数 |
| --- | ---: |
| 台账闭合（无未判、无待取、无待判全文） | 26 |
| 未闭合：`nutrition-electrolytes`（10 篇全未判） | 1 |
| 未闭合：`nutrition-ckd-risk`（1 篇未判） | 1 |

生产已发布卡片 **52** 张，覆盖 **12** 个 condition。

## 五、结论

主线的真实状态不是"缺证据"或"缺模型能力"：

1. **26 / 28 个主题的台账是闭的**，52 张卡已发布。
2. **147 条无全文是版权终态**，不是待办，也不会因为"再跑一次采集"而改变。
3. **只有 4 篇是真正待取全文**，且它们全部卡在 ADR 0015 修掉的那一个死锁上。

**因此下一步不是补采集，也不是换模型，而是确认修复在生产上生效的那 4 篇。**
本记录写下的三个数字（79 / 121→151 / 28 主题）以后若要引用，必须带上各自的
分流口径，否则它们会再一次被读成"有一大批活没干"。
