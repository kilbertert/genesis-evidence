# Portal API 与 health-flow 适配器

`portal/api.py` 是仓库唯一的对外 HTTP 面：`POST /api/evidence/matches`，只读证据
查询。无 OpenAPI/docs 端点。注意区分文件留存与线上路由：`GET /` 返回的是 JSON
服务信息（`{"service", "scope"}`）而非页面——公开域名上的入口页由 health-flow 侧
提供；`portal/index.html` 只是留存的静态工件（ADR 0019/0020 决定其角色），不等于
本服务对外渲染的首页。

## 请求契约

- **鉴权**：`X-Genesis-Evidence-Key` 头，`hmac.compare_digest` 比对，密钥
  `create_app` 时要求 ≥24 字符。注意 `.spec/patient-path/portal-api` 仍写
  "Bearer/RFC 6750"——那是 review 端点的规格措辞漂移，portal 用 API-key 头。
- **`X-Correlation-Id`**：必须是 UUID 否则 400；缺省自动生成。
- **请求模型**：`schema_version: Literal["2","3"]`，全部模型 `extra="forbid"`，
  `observation_id` 唯一、≤600 行。
- **响应重校验**：返回前再过 `EvidenceMatchResponse`/`V2` 模型 dump——服务端
  构造的响应也必须满足对外 schema，不守信手构造。
- **安全头中间件**：CSP / no-store / no-referrer，每响应附加。

## 失效语义（重要）

- `ValueError`（未知 metric、值/界不在 evidence、low>high、bad correlation id）
  → 400 → **同一事务回滚 → 无审计行**。整请求拒绝，无部分结果；被拒请求按构造
  不被审计。
- 审计 `detail_json` = 计数 + `metric_codes` + `card_ids` + correlation_id——
  **不含**观测 ID、数值或患者标识。审计内容边界是契约。

## health-flow 适配器（integrations/health_flow.py）

把 health-flow 的报告行转成 v3 请求。**永不抛异常**：每个失败把该行落 `skipped`
并声明原因，处理继续。管道：别名解析 → 页码 → 单位（`DIMENSIONLESS_METRICS` 得
`"1"`）→ 值在 evidence 中 → 界在 evidence 中 → 文件索引 → bbox。

- `confirmed=False` 输入 → 空请求 + 每行 `skipped: confirmation_required`
  （整包拒绝，不降级处理）。
- `uncovered` 属性 = `is_unreadable` 行（`unknown_metric_code`）——刻意不是
  "异常的不可读行"计数。
- 新增生产者 reason 必须在 `PRODUCER_ELIGIBLE_REASONS`（见
  kernel/vocabulary-modules.mdx），否则 `test_disposition.py` 按源码抽取失败。

## 启动 fail-fast

`create_app` 在缺/短 API key、缺 DB 文件、缺 `_REQUIRED_EVIDENCE_TABLES` 中任一
必需表时抛 `ValueError`——绝不降级启动。portal 与 review 的建表行为不对称（见
persistence/database-invariants.mdx）：portal 不建表，`bootstrap-db.py` 必须先跑。
