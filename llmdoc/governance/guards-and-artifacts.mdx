# 治理工件与 CI guard 边界

每个 guard 的"不覆盖什么"和覆盖什么一样是契约。

## guard 边界表

| 脚本 | 范围 | 执行 | 刻意不覆盖 |
|---|---|---|---|
| `check_schema.py` | 新库表数 vs `MAX_TABLES = 26` | CI（quality） | 不校验列/索引——那是 schema CHECK+测试的活 |
| `check_scope.py` | **13 个冻结标识符**（`care_task`、`electronic_signature`、`followup`、`intervention_plan`、`nutrition_product`、`organization`、`professional_note`、`rbac`、`record_share`、`service_event`、`supplier_product`、`supplement_recommendation`、`test_plan`）大小写折叠子串匹配，文件名与路径都算 | CI | 只扫 `src/genesis_evidence/` 下 `.py/.html/.js/.css/.toml`——冻结的是领域扩张，不是字符串洁癖 |
| `check_patient_copy.py` | `FORBIDDEN_PATIENT_TERMS` 子串扫 `src/genesis_evidence/portal/**` 固定路径集（`.py/.html/.js/.jsx/.ts/.tsx/.vue`） | CI | **只扫 portal/**——`_automatic_profile` 模板正文等其余写入路径只靠运行时 `validate_patient_copy`；两处覆盖不重叠是有意的 |
| `check_review_workbench_layout.py` | headless Chrome 探 workbench 布局：桌面 flex+`main overflow:hidden`+aside/.content 独立滚动+窗不滚动+双视图切换；移动 390px 无横滚 | **本地专用**（不在 CI） | 需 `google-chrome`/`chromium` 二进制；无浏览器报 `RuntimeError` 不是通过 |

## 被 test_governance_artifacts.py 钉住的工件结构

- `acceptance.feature`：以 `Feature:` 开头，含 4 个钉死场景名，含逐字
  `、` 连接的 `FORBIDDEN_PATIENT_TERMS` 串（「诊断、确诊、处方、治愈、根治、排毒、
  抗癌、逆龄」）。
- `qa-plan.md`：恰 6 个钉死用例 ID（`QA-EVID-001..004`、`QA-DISEASE-001`、
  `QA-WORKBENCH-001`），每个有非空 `**ID**/**环境**/**前置**/**数据**/
  **可观察结果**/**清理** + `**动作**` + 有序动作表。增删用例=改测试里
  `QA_CASE_IDS`。
- `GLOSSARY.md`：钉死的术语集（证据/目录轴/成分轴）；**不得**含 `## Decision`
  或 `## 数据与迁移` 标题（术语表≠ADR）；`condition` 行必须声明它可独立于报告项
  存在。
- ADR 形状门：`docs/adr/{0005,0006,0007,0008}` 必须含 `## Decision`、
  `## Alternatives Considered`、`## Rationale`。更宽的决策记录检查是
  `.sandcastle/adr.check.mjs`（afk-policy 工作流驱动）。

**改动顺序**：改"允许说什么"时先改 `acceptance.feature`/`qa-plan.md` 声明意图，
再改词表，再改代码——工件是先于代码的契约声明。

## CI 拓扑

默认分支 ruleset 必过：**`quality` + `Workflow policy`**。

| 工作流 | 门禁 |
|---|---|
| `quality.yml` | ruff、pytest、check_scope、check_schema、check_patient_copy、`profile-network.check.ts`（loopback-only profile 得 `--network host`）、`architecture-review/output.check.ts`（可 skipped） |
| `afk-policy.yml` → `Workflow policy` | `policy-check.mjs workflows` + profile-network；`fetch-depth: 0` 拿 merge-base |
| `spec-tree.yml` | `spex spec lint`（必须全量历史，见 spec-tree.mdx） |
| `agent-*.yml` | label 门控（`agent:implement`/`agent:review`/`agent:update-branch`），仅 owner-authored 同仓 PR；见 agent-workflow/afk-control-plane.mdx |
| `architecture-review.yml` | 工作日 cron，<10 个开放非 bug 提案封顶 |
| `gitlab-mirror.yml` | 全 ref 裸镜像到公司 GitLab `ai-products/genesis-evidence` |
| `sandbox-image.yml` | `.sandcastle/Dockerfile` 变更时发镜像到 ghcr |
